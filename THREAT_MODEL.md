# Threat model

What an attacker can try against a Samepage instance, what stops it, and where that is tested. The last two sections list what is accepted and what is not mitigated. Isolation is enforced in `samepage/core/policy.py` and `samepage/services/access.py` before a view loads the target row; `tests/test_authz_matrix.py` sends every route to seven principals (anonymous, two participants, two judges, the organizer, the admin) in every format and fails when a new route has no row.

## Covered

| Threat | What we do | Where it is tested |
|---|---|---|
| A judge reads a peer's scores by URL | `scores.read_named` is denied unless the slug is the caller's own id or the caller is staff. The check runs before the row is loaded, so the answer is 403 in HTML, JSON and CSV for every other id, existing or not. | `tests/test_http.py`, `tests/test_authz_matrix.py`, `run.py` |
| A participant opens a score URL | `scores.read_own` requires the judge role: 403, including on `/judges/me/scores`. A stranger gets 401. | `tests/test_http.py`, `tests/test_authz_matrix.py`, `run.py` |
| Deadline bypass by a client clock | The service and a trigger both compare with the database clock. Imports are judged on their own `submitted_at`, so seeding a closed event does not trip the trigger. | `run.py` (409), `tests/test_http.py`, `tests/test_lifecycle.py` |
| Cutoff gaming | After the deadline the service answers 409 before it reads the body, and the triggers refuse the insert, content edits and image changes even if the application is bypassed. Teams freeze at the deadline too. Moving the deadline is an organizer action, audited with the old and new times. | `tests/test_lifecycle.py` |
| Scoring after judging ends | When 'Judging ends' is set, saving and finalizing a score answer 409 after it, on the database clock, until an organizer moves it. | `tests/test_event_windows.py` |
| Format confusion | The suffix wins, else the `Accept` header; `?format=` is ignored; an unknown suffix is 404; an error on a `.json` or `.csv` URL is problem+json even when it happens before any view runs. | `tests/test_http.py`, `tests/test_authz_matrix.py` |
| Web cache deception | A path like `/judges/me/scores.json/x.csv` matches no route, so it is 404, never a private body under a cacheable name. | no automated test |
| CSRF on cookie sessions | Enforced for signed-in writes (DRF session authentication) and for the anonymous writes that start a session, `POST /login`, `POST /signup`, `POST /password/<token>` and `POST /demo/enter/<slug>`, which check the token themselves. Bearer requests are exempt because they are not cookie sessions. | `tests/test_sessions.py`, `tests/test_lifecycle.py`, `tests/test_e2e_browser.py` |
| Login CSRF through a GET | `/demo/enter/<slug>` answers a GET with a page and a button; only the POST signs in. | `tests/test_sessions.py` |
| Password guessing | `POST /login`, `POST /signup` and `POST /password/<token>` share one throttle, 10 a minute per client address (the TCP peer, unless `SAMEPAGE_NUM_PROXIES` is set). The count is kept in Postgres, so every gunicorn worker shares it. GET routes are never throttled. Passwords are PBKDF2 hashes, 10 characters or more, and never the published demo password. | `tests/test_sessions.py` (the sign-in limit, shared by workers), `tests/test_lifecycle.py` (password rules) |
| Open redirect after sign-in | `next` is followed only when it stays on this host. | `tests/test_sessions.py` |
| Login redirect hiding a 401 | No redirects on refusal. The HTML sign-in form is rendered with status 401 and `WWW-Authenticate: Bearer`; JSON and CSV get problem+json. | `tests/test_http.py`, `tests/test_authz_matrix.py` |
| Tracebacks in error bodies | DEBUG is off outside demo mode and off by default in demo mode. A 500 returns a problem body with a reference id and no stack; the stack goes to the log with the same id. | `tests/test_writes.py` |
| Bad input causing 500s | Bodies must be objects, text fields must be text, tracks must belong to the event, a final score is 409, an illegal state change is 409, a trigger refusal is 409. Refused requests roll back. A NUL character anywhere in a body or query string (Postgres text cannot hold one) is 422 naming the field, including anonymous `POST /login` and `POST /signup`. A well-formed but impossible date (`2026-02-30`) is 422. | `tests/test_writes.py`, `tests/test_input_guards.py` |
| Reading a draft event by id | A draft event is 404 to everyone but its organizers and admins, by id as well as in the list, on every route after the policy check, so the answer matches an id that does not exist. Teams cannot form until it is open. | `tests/test_event_windows.py`, `tests/test_lifecycle.py` |
| Reading a draft submission | A draft and its images are 403 to everyone but its team and the organizers, and drafts are not in the gallery. | `tests/test_lifecycle.py`, `tools/lifecycle_check.py` |
| Formula injection in CSV | Text cells that start with `= + - @`, a tab or a carriage return get a leading quote. | `tests/test_writes.py` |
| XSS | Templates autoescape and no user field is marked safe. The CSP is `default-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'`, and there is no inline script. | no automated test |
| Public demo credentials in production | Production mode refuses to start while demo tokens or the demo password are in the database, or while the secret key, a database password or `ALLOWED_HOSTS=*` is a default. At request time a demo token is 401, the demo password never signs in, and `/demo/enter/*` is 404. | `tests/test_production.py`, CI `production` job ([receipts](receipts/production-refusal-demo-db.txt)) |
| Stolen or guessed invite links | Team links carry 24 random bytes, are stored as sha256 only, shown once, and have an expiry, a use limit and revoke. Joining needs an account; judges, organizers and admins cannot join; a team has a size cap; team changes stop at the deadline. Each create, join and revoke is audited. | `tests/test_lifecycle.py` |
| Taking a judge or organizer role by registering the invitee's email first | Inviting an address never attaches a role to an account someone could already be using. A new address gets an account with no password, the role, and a one-time set-password link; sign-up with that address is then 409, so only the link holder can use it. An account that already exists (and has a password, a role or a team) gets a one-time acceptance link instead (sha256 stored, 14 days, a new one revokes the old); the role is created when that account, signed in, accepts it, and any other account gets 403. Unaccepted invitations are listed as such on the people page. | `tests/test_role_invites.py` |
| Account takeover through a set-password link | A link is one use, expires in 14 days, and a new link revokes the old. An organizer gets one only for an account that has never had a password and has no role on another event, so an organizer of one event cannot take over a judge, an admin or anyone else's account. | `tests/test_judging_flow.py` |
| Hostile uploads | Images only: the type is sniffed from the first bytes (PNG, JPEG, GIF, WebP; SVG and HTML are refused), at most 2 MB, served with the sniffed type, `nosniff` and `Content-Security-Policy: default-src 'none'; sandbox`. A draft's images are private like the draft. | `tests/test_lifecycle.py` |
| Changing the outcome after publish | Scores, unlocks, weights and settings, duplicate decisions, issuing, top-ups, manual assignments, abandoning batches, judge invitations and withdrawals answer 409 once published, and every reader gets the snapshot stamped at publish. | `tests/test_judging_flow.py`, `tests/test_role_invites.py` |
| A draft or reopened score deciding the ranking | Only reviews whose every criterion is final are counted; the rest are in `scores.csv` with the reason. A final score changes only through the organizer's audited unlock, and a trigger refuses any other rev after a final one. | `tests/test_judging_flow.py`, `tests/test_writes.py` |
| Team identity under blind judging | With blind judging on, judges (who are not also organizers) do not receive the team name or id from the gallery, in HTML, JSON or CSV (the field policy table decides), or from the project page. | `tests/test_writes.py` |
| Judge collusion or bias | A judge is never assigned a project whose team has their email, or a team they have a `coi` row for. The adjusted score removes each judge's measured lean; the lab lists every judge's lean and flags straight-line and no-variance judges; leave-one-judge-out names the judges whose removal changes the top 5. | `tests/domain/test_assign.py`, `tests/domain/test_flags.py`, `tests/domain/test_reml.py` |
| Webhook SSRF attacks | Endpoint URLs are validated before registration and delivery: DNS is resolved and IP addresses in loopback (127.0.0.0/8), private networks (RFC 1918), link-local (169.254.0.0/16 including AWS/GCP metadata), and IPv6 equivalents are strictly refused. | `tests/test_webhooks.py` |
| Webhook payload tampering & replay | Deliveries implement Standard Webhooks v1: `webhook-id`, `webhook-timestamp`, and `webhook-signature` using HMAC-SHA256 (`v1,<base64>`). Secrets are generated with 32 cryptographically secure random bytes (`whsec_...`). | `tests/test_webhooks.py` |
| Tampering with published evaluation records | RFC 9162 Merkle tree calculated over canonical review leaves; Merkle root is signed with the event's Ed25519 keypair. Judge protocols contain audit inclusion proofs allowing judges to mathematically verify their reviews were counted without alteration. | `tests/test_signing.py` |
| Fake or altered award certificates | Each certificate embeds a canonical payload hash, Ed25519 cryptographic signature, and public key PEM inside a self-contained SVG. Validatable offline or online via `/certificates/<cert_no>`. | `tests/test_certificates.py` |
| Premature feedback leak | Participant feedback packs remain inaccessible (403) until results are published and organizers explicitly release feedback via an audited release action. | `tests/test_feedback.py`, `tests/test_authz_matrix.py` |
| Ballot stuffing & sybil voting | A ballot's credits may not exceed the budget, and c credits on a project give √c influence. Each voter has a unique hash per event; a second ballot from the same voter updates the first rather than counting twice. Magic-link requests are throttled (`SAMEPAGE_MAGIC_LINK_RATE`, 5/min by default) and a link expires after 15 minutes. | `tests/test_voting.py` |
| Public comment spam & harassment | All public project comments enter a `pending` state and require explicit organizer approval (`comments.moderate`) before becoming visible. Comment submission is throttled (10 per hour per IP). | `tests/test_comments.py`, `tests/test_throttles.py` |
| Malformed or malicious bundle import | Imports are strictly validated against the event bundle schema (a superset of `fixtures.json`), require global admin authorization, map internal IDs cleanly, enforce referential integrity, and execute in an atomic transaction that rolls back on any violation. | `tests/test_bundle.py` |

Cache-Control is `private, no-store` on every response to a request with a session cookie or an `Authorization` header, and on every 4xx or 5xx. Anonymous GETs of public pages (the home page, the gallery, project pages, images, `/about/access`, and results after publish) are `public, max-age=30`, with `Access-Control-Allow-Origin: *` on those GETs. Unpublished results are 403 with `no-store`, including for anonymous clients.

## Accepted

- **Staff learn which judge ids exist.** A judge gets 403 for every other id, existing or not, so that answer reveals nothing. An organizer asking for an id that never judged the event gets 404; organizers can list the judges anyway.
- **A database owner can edit rows.** Triggers stop the runtime role and ordinary bugs. They do not stop the owner. The audit hash chain and any downloaded CSV show the change afterwards. Nothing is signed.
- **No row-level security.** Isolation is the policy module. A view that forgot to call it would be a bug. Every route calls it in `SamepageView.initial`, and the authorization matrix covers every route.
- **The owner password is in the app environment** during migrate, and Compose passes it in. Anyone who can `docker exec` into the app container is the owner.
- **Demo mode is open on purpose.** Anyone who can reach a demo-mode portal can press a demo button and be the organizer. Compose publishes the port on 127.0.0.1 only for that reason.
- **The gallery shows each project's review count** to visitors before results are published.
- **Open sign-up.** Anyone who can reach the portal can create accounts, with any email address (no email verification, no captcha; only the throttle). An account alone reaches nothing private: it can start a team, join one with a link, and get a judge or organizer role only by accepting the link the organizer gave the invitee. Someone who registers an invitee's address first cannot take the role, but can keep that person from using that address; the organizer then invites another one.
- **The public gallery shows every track to judges.** Track scoping covers assignment, the console and scores, not the public gallery ([JUDGING.md](JUDGING.md#assignment)).

## Not mitigated

- **Sybil email accounts.** Public voting magic links and signups rely on email identity and rate throttling; an adversary with many distinct external email addresses can request multiple voting links. Verified participant votes are separated and weighted higher to preserve voting integrity.
- **Scraping.** Public pages and published results are meant to be read, and GETs are not throttled or rate-limited. Private data needs a role; there is no protection against bulk download of what is public.
- **Transport security.** The app speaks plain HTTP. TLS belongs on a reverse proxy, and today a TLS-terminating proxy breaks browser form posts (the CSRF origin check sees `http`; README, Limits). Without TLS, passwords and session cookies cross the network in clear text.
- **Collusion the data cannot show.** Two judges who agree to inflate one project look like two judges who like it. The lean estimate and leave-one-judge-out show influence; they do not prove intent.
- **Denial of service.** No request size limit beyond Django's defaults and the 2 MB image cap, no per-client limit on writes other than the sign-in throttle, and a results read after a change runs a fit of a few seconds.
